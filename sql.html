Chapitre 1 — Fondamentaux
LEÇON 01

Introduction à SQL

SQL — Structured Query Language — est le langage universel de communication avec les bases de données relationnelles. Il permet de créer, modifier, supprimer et consulter des données.

On le retrouve partout : sites web, banques, réseaux sociaux, applications mobiles. Les systèmes majeurs incluent MySQL, PostgreSQL, MariaDB, SQL Server et Oracle.

SELECT 'Bonjour SQL';
LEÇON 02

Comprendre une Base de Données

Une base de données est un ensemble organisé d'informations stockées électroniquement. Pensez à une bibliothèque : les rayons sont les tables, les livres sont les lignes, les étiquettes sont les colonnes.

Base de données
 └── Table utilisateurs
      ├── id
      ├── nom
      └── email
LEÇON 03

Les Tables

Une table est l'élément central d'une base de données. Elle s'organise en lignes (enregistrements) et colonnes (caractéristiques).

CREATE TABLE utilisateurs (
  id    INT,
  nom   VARCHAR(100),
  email VARCHAR(150)
);
LEÇON 04

Colonnes et Types de Données

Chaque colonne accepte un type de données précis. Voici les plus courants :

INTNombre entier (42, -7, 1000)
VARCHARTexte de longueur variable
DATEDate (2025-01-31)
FLOATNombre décimal (3.14)
BOOLEANVrai ou faux
CREATE TABLE produits (
  id   INT,
  nom  VARCHAR(100),
  prix FLOAT
);
LEÇON 05

Créer et Sélectionner une Base

Avant de créer des tables, il faut créer un conteneur : la base de données. Puis la sélectionner pour y travailler.

CREATE DATABASE ecole;

USE ecole;
Chapitre 2 — Lecture et Filtrage
LEÇON 06

Insérer des Données

INSERT INTO ajoute de nouvelles lignes dans une table. Précisez les colonnes et leurs valeurs correspondantes.

INSERT INTO utilisateurs (nom, email)
VALUES ('Ali', 'ali@gmail.com');
LEÇON 07

Afficher les Données — SELECT

SELECT est la commande la plus utilisée en SQL. L'étoile * récupère toutes les colonnes.

-- Toutes les colonnes
SELECT * FROM utilisateurs;

-- Colonnes spécifiques
SELECT nom, email FROM utilisateurs;
💡 En production, évitez SELECT * et listez uniquement les colonnes nécessaires pour de meilleures performances.
LEÇON 08

Filtrer avec WHERE

WHERE filtre les résultats selon une condition. Seules les lignes correspondantes sont retournées.

SELECT * FROM utilisateurs
WHERE id = 1;
LEÇON 09

Trier avec ORDER BY

ORDER BY classe les résultats. ASC pour croissant, DESC pour décroissant.

SELECT * FROM utilisateurs
ORDER BY nom ASC;

SELECT * FROM produits
ORDER BY prix DESC;
LEÇON 10

DISTINCT — Supprimer les Doublons

DISTINCT élimine les valeurs répétées. Si trois clients habitent à Dakar, la ville n'apparaît qu'une fois.

SELECT DISTINCT ville FROM clients;
LEÇON 11

Les Opérateurs de Comparaison

Ces opérateurs s'utilisent dans les clauses WHERE pour affiner les conditions :

=Égal à
!=Différent de
>Supérieur à
<Inférieur à
>=Supérieur ou égal
<=Inférieur ou égal
SELECT * FROM produits
WHERE prix > 1000;
LEÇON 12

AND, OR, NOT

Ces opérateurs logiques combinent plusieurs conditions :

-- AND : toutes les conditions doivent être vraies
SELECT * FROM employes
WHERE salaire > 200000
  AND ville = 'Dakar';

-- OR : au moins une condition vraie
SELECT * FROM employes
WHERE ville = 'Dakar'
   OR ville = 'Thiès';

-- NOT : exclure une valeur
SELECT * FROM clients
WHERE NOT ville = 'Dakar';
LEÇON 13

LIKE — Recherche Partielle

LIKE effectue des recherches dans les textes. Le symbole % représente n'importe quelle suite de caractères, _ représente un seul caractère.

-- Noms commençant par A
SELECT * FROM clients WHERE nom LIKE 'A%';

-- Noms finissant par a
SELECT * FROM clients WHERE nom LIKE '%a';

-- Contient "ali"
SELECT * FROM clients WHERE nom LIKE '%ali%';
LEÇON 14

BETWEEN et IN

BETWEEN sélectionne une plage de valeurs. IN teste plusieurs valeurs en une seule condition.

-- Plage de prix
SELECT * FROM produits
WHERE prix BETWEEN 1000 AND 5000;

-- Plusieurs villes
SELECT * FROM clients
WHERE ville IN ('Dakar', 'Thiès', 'Saint-Louis');
LEÇON 15

LIMIT — Limiter les Résultats

Indispensable sur les grandes tables pour ne récupérer qu'un sous-ensemble de lignes.

-- 10 premiers résultats
SELECT * FROM utilisateurs LIMIT 10;

-- Pagination : ignorer 20 lignes, prendre les 10 suivantes
SELECT * FROM utilisateurs LIMIT 10 OFFSET 20;
Chapitre 3 — Modification et Agrégation
LEÇON 16

Mettre à Jour — UPDATE

Modifie les données existantes. Utilisez toujours WHERE pour cibler les lignes concernées.

UPDATE utilisateurs
SET email = 'nouveau@gmail.com'
WHERE id = 1;
⚠️ Un UPDATE sans WHERE modifie TOUTES les lignes de la table. Testez toujours votre WHERE avec un SELECT avant.
LEÇON 17

Supprimer — DELETE

Supprime définitivement des enregistrements. Cette opération est irréversible sans sauvegarde.

DELETE FROM utilisateurs
WHERE id = 1;
⚠️ Comme pour UPDATE, un DELETE sans WHERE vide entièrement la table.
LEÇON 18

Les Valeurs NULL

NULL représente l'absence d'information — ni zéro, ni chaîne vide. Utilisez IS NULL ou IS NOT NULL pour les détecter.

-- Utilisateurs sans téléphone
SELECT * FROM utilisateurs WHERE telephone IS NULL;

-- Utilisateurs avec téléphone
SELECT * FROM utilisateurs WHERE telephone IS NOT NULL;
LEÇON 19

Fonctions d'Agrégation

Ces fonctions effectuent des calculs sur un ensemble de lignes et retournent une valeur unique :

-- Nombre d'utilisateurs
SELECT COUNT(*) FROM utilisateurs;

-- Somme des ventes
SELECT SUM(prix) FROM commandes;

-- Prix moyen
SELECT AVG(prix) FROM produits;

-- Prix le plus bas / le plus haut
SELECT MIN(prix), MAX(prix) FROM produits;
LEÇON 20

GROUP BY et HAVING

GROUP BY regroupe les lignes partageant une même valeur. HAVING filtre les groupes (comme WHERE mais pour les agrégats).

-- Nombre de clients par ville
SELECT ville, COUNT(*) AS total
FROM clients
GROUP BY ville;

-- Villes avec plus de 5 clients
SELECT ville, COUNT(*) AS total
FROM clients
GROUP BY ville
HAVING COUNT(*) > 5;
LEÇON 21

Les Alias — AS

Les alias donnent un nom lisible aux colonnes ou aux tables dans les résultats et les requêtes complexes.

SELECT nom   AS Nom_Client,
       email  AS Adresse_Email
FROM utilisateurs;
Chapitre 4 — Jointures et Requêtes Avancées
LEÇON 22

Introduction aux Jointures

Les bases de données relationnelles répartissent les données dans plusieurs tables. Les jointures permettent de les combiner en une seule requête en reliant les tables via des colonnes communes.

💡 Exemple classique : relier la table clients à la table commandes via client_id.
LEÇON 23

INNER JOIN

Retourne uniquement les lignes ayant une correspondance dans les deux tables. Les enregistrements sans correspondance sont exclus.

SELECT clients.nom,
       commandes.date_commande
FROM clients
INNER JOIN commandes
  ON clients.id = commandes.client_id;
LEÇON 24

LEFT JOIN et RIGHT JOIN

LEFT JOIN retourne toutes les lignes de la table gauche, même sans correspondance à droite (valeur NULL dans ce cas). RIGHT JOIN fait l'inverse.

-- Tous les clients, même sans commande
SELECT clients.nom, commandes.id
FROM clients
LEFT JOIN commandes
  ON clients.id = commandes.client_id;

-- Toutes les commandes, même sans client lié
SELECT clients.nom, commandes.id
FROM clients
RIGHT JOIN commandes
  ON clients.id = commandes.client_id;
LEÇON 25

FULL JOIN et UNION

FULL JOIN combine les deux : toutes les lignes des deux tables. UNION fusionne les résultats de deux SELECT compatibles (doublons supprimés automatiquement).

-- FULL JOIN
SELECT * FROM clients
FULL JOIN commandes
  ON clients.id = commandes.client_id;

-- UNION : liste unique de noms
SELECT nom FROM clients
UNION
SELECT nom FROM fournisseurs;
LEÇON 26

Les Sous-Requêtes

Une sous-requête est une requête imbriquée dans une autre. Elle permet des opérations en plusieurs étapes.

-- Produits au-dessus du prix moyen
SELECT * FROM produits
WHERE prix > (
  SELECT AVG(prix) FROM produits
);

-- Clients ayant passé une commande
SELECT nom FROM clients
WHERE EXISTS (
  SELECT * FROM commandes
  WHERE commandes.client_id = clients.id
);
LEÇON 27

ANY et ALL

ANY compare à au moins une valeur de la sous-requête. ALL compare à toutes les valeurs.

-- Plus cher qu'au moins un article en promo
SELECT * FROM produits
WHERE prix > ANY (SELECT prix FROM promotions);

-- Plus cher que tous les articles en promo
SELECT * FROM produits
WHERE prix > ALL (SELECT prix FROM promotions);
Chapitre 5 — Structure, Sécurité et Optimisation
LEÇON 28

Les Index

Les index accélèrent les recherches sur les grandes tables, comme un index de livre. Créez-en sur les colonnes fréquemment utilisées dans les WHERE.

CREATE INDEX idx_nom
ON utilisateurs(nom);

-- Index sur plusieurs colonnes
CREATE INDEX idx_ville_statut
ON clients(ville, statut);
💡 Les index accélèrent la lecture mais ralentissent légèrement l'écriture. Utilisez-les avec discernement.
LEÇON 29

Clés Primaires et Étrangères

La clé primaire identifie chaque ligne de façon unique. La clé étrangère crée un lien vers une autre table et garantit l'intégrité des données.

CREATE TABLE clients (
  id  INT PRIMARY KEY,
  nom VARCHAR(100) NOT NULL
);

CREATE TABLE commandes (
  id        INT PRIMARY KEY,
  client_id INT,
  FOREIGN KEY (client_id)
    REFERENCES clients(id)
);
LEÇON 30

Contraintes NOT NULL et UNIQUE

NOT NULL rend un champ obligatoire. UNIQUE interdit les doublons dans une colonne.

CREATE TABLE utilisateurs (
  id    INT PRIMARY KEY,
  nom   VARCHAR(100) NOT NULL,
  email VARCHAR(200) UNIQUE
);
LEÇON 31

Les Transactions — START, COMMIT, ROLLBACK

Une transaction regroupe plusieurs opérations en une seule unité atomique. Si une opération échoue, tout peut être annulé.

START TRANSACTION;

UPDATE comptes SET solde = solde - 500 WHERE id = 1;
UPDATE comptes SET solde = solde + 500 WHERE id = 2;

-- Tout s'est bien passé
COMMIT;

-- En cas d'erreur : tout annuler
ROLLBACK;
💡 Les transactions sont indispensables dans les systèmes bancaires et les paiements en ligne.
LEÇON 32

Les Vues — VIEW

Une vue est une table virtuelle basée sur une requête SQL. Elle simplifie les requêtes complexes et peut restreindre l'accès à certaines colonnes sensibles.

-- Créer une vue
CREATE VIEW vue_clients AS
SELECT nom, email FROM clients;

-- Utiliser la vue comme une table
SELECT * FROM vue_clients;
LEÇON 33

ALTER TABLE — Modifier une Table

Permet d'ajouter, modifier ou supprimer des colonnes sur une table existante.

-- Ajouter une colonne
ALTER TABLE utilisateurs ADD telephone VARCHAR(20);

-- Modifier un type
ALTER TABLE utilisateurs MODIFY nom VARCHAR(200);

-- Supprimer une colonne
ALTER TABLE utilisateurs DROP COLUMN telephone;
LEÇON 34

DROP et TRUNCATE

DROP TABLE supprime la table entièrement. TRUNCATE vide son contenu mais conserve la structure.

-- Vider le contenu (structure conservée)
TRUNCATE TABLE logs;

-- Supprimer la table définitivement
DROP TABLE IF EXISTS ancienne_table;
⚠️ Ces opérations sont irréversibles. Sauvegardez avant d'exécuter.
LEÇON 35

AUTO_INCREMENT

Génère automatiquement un identifiant unique pour chaque nouvelle ligne.

CREATE TABLE articles (
  id      INT AUTO_INCREMENT PRIMARY KEY,
  titre   VARCHAR(200) NOT NULL,
  contenu TEXT
);
LEÇON 36

DEFAULT — Valeur par Défaut

Définit une valeur automatique si aucune valeur n'est fournie lors de l'insertion.

CREATE TABLE commandes (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  statut     VARCHAR(50) DEFAULT 'en attente',
  created_at DATETIME    DEFAULT NOW()
);
LEÇON 37

Fonctions de Chaîne

SQL propose de nombreuses fonctions pour manipuler le texte.

SELECT UPPER(nom)           AS nom_majuscule,
       LOWER(email)          AS email_minuscule,
       LENGTH(nom)           AS longueur,
       CONCAT(prenom, ' ', nom) AS nom_complet
FROM utilisateurs;
LEÇON 38

Fonctions de Date

Manipulez et formatez les dates directement en SQL.

SELECT NOW()                        AS maintenant,
       YEAR(date_naissance)          AS annee,
       DATEDIFF(NOW(), created_at)   AS jours_anciennete
FROM utilisateurs;
LEÇON 39

CASE WHEN — Conditions dans SELECT

Permet d'ajouter une logique conditionnelle directement dans une requête.

SELECT nom,
  CASE
    WHEN salaire > 500000 THEN 'Senior'
    WHEN salaire > 200000 THEN 'Confirmé'
    ELSE                       'Junior'
  END AS niveau
FROM employes;
LEÇON 40

COALESCE et IFNULL

Retournent une valeur de remplacement si la valeur est NULL.

-- COALESCE : retourne la première valeur non-NULL
SELECT COALESCE(telephone, email, 'Non renseigné') AS contact
FROM utilisateurs;

-- IFNULL (MySQL)
SELECT IFNULL(telephone, '—') AS tel FROM utilisateurs;
LEÇON 41

Les Procédures Stockées

Un bloc de code SQL enregistré dans la base et réutilisable à la demande.

DELIMITER //

CREATE PROCEDURE AfficherClients()
BEGIN
  SELECT * FROM clients;
END //

DELIMITER ;

CALL AfficherClients();
LEÇON 42

Les Déclencheurs — TRIGGER

Un trigger exécute automatiquement du code SQL lors d'un événement (INSERT, UPDATE, DELETE).

CREATE TRIGGER avant_suppression
BEFORE DELETE ON clients
FOR EACH ROW
BEGIN
  INSERT INTO archive_clients (nom, email)
  VALUES (OLD.nom, OLD.email);
END;
LEÇON 43

La Gestion des Utilisateurs

Créez des comptes avec des droits limités pour sécuriser votre base de données.

-- Créer un utilisateur
CREATE USER 'ali'@'localhost'
IDENTIFIED BY 'motdepasse_fort';

-- Accorder des droits
GRANT SELECT, INSERT ON ecole.*
TO 'ali'@'localhost';

-- Révoquer
REVOKE INSERT ON ecole.*
FROM 'ali'@'localhost';
LEÇON 44

Les Fonctions de Fenêtre — OVER

Les fonctions fenêtre effectuent des calculs sur un groupe de lignes lié à la ligne courante, sans grouper les résultats.

SELECT nom,
       salaire,
       RANK() OVER (ORDER BY salaire DESC) AS classement,
       AVG(salaire) OVER ()                AS moy_globale
FROM employes;
LEÇON 45

CTE — Common Table Expressions

Les CTE (WITH) créent des résultats intermédiaires nommés, rendant les requêtes complexes bien plus lisibles.

WITH clients_actifs AS (
  SELECT * FROM clients
  WHERE statut = 'actif'
)
SELECT ca.nom, COUNT(c.id) AS nb_commandes
FROM clients_actifs ca
LEFT JOIN commandes c ON ca.id = c.client_id
GROUP BY ca.nom;
LEÇON 46

EXPLAIN — Analyser les Performances

Affiche le plan d'exécution d'une requête pour identifier les goulets d'étranglement et optimiser.

EXPLAIN SELECT * FROM utilisateurs
WHERE email = 'ali@gmail.com';
💡 Si la colonne type affiche ALL, une table entière est parcourue. Ajoutez un index !
LEÇON 47

La Normalisation

Organiser les données en plusieurs tables liées pour éviter la redondance et garantir la cohérence. Les formes normales (1NF, 2NF, 3NF) guident cette organisation.

-- Au lieu de stocker la ville en texte dans chaque client :
CREATE TABLE villes (
  id  INT PRIMARY KEY,
  nom VARCHAR(100)
);

ALTER TABLE clients ADD ville_id INT;
ALTER TABLE clients ADD FOREIGN KEY (ville_id) REFERENCES villes(id);
LEÇON 48

La Sauvegarde et la Restauration

Exportez et importez votre base de données pour la sauvegarder ou la migrer.

-- Exporter (dans le terminal)
mysqldump -u root -p ecole > sauvegarde.sql

-- Restaurer
mysql -u root -p ecole < sauvegarde.sql
LEÇON 49

Les Injections SQL — Se Protéger

L'injection SQL est une attaque qui insère du code malveillant dans une requête. Ne jamais construire des requêtes par concaténation de chaînes.

-- ❌ DANGEREUX
"SELECT * FROM users WHERE nom = '" + input + "'"

-- ✅ SÉCURISÉ — requêtes préparées (PDO, PHP)
$stmt = $pdo->prepare(
  "SELECT * FROM users WHERE nom = ?"
);
$stmt->execute([$input]);
⚠️ Utilisez toujours des requêtes préparées ou des ORM dans vos applications.
