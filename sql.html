Chapitre 1 — Fondamentaux
LEÇON 01

Introduction à SQL

SQL — Structured Query Language — est le langage standardisé pour communiquer avec les bases de données relationnelles. Conçu en 1974 par IBM, il est devenu la lingua franca universelle du monde des données.

SQL repose sur quatre grandes familles de commandes :

DDLData Definition Language — Crée et modifie la structure (CREATE, ALTER, DROP)
DMLData Manipulation Language — Manipule les données (SELECT, INSERT, UPDATE, DELETE)
DCLData Control Language — Gère les droits d'accès (GRANT, REVOKE)
TCLTransaction Control Language — Gère les transactions (COMMIT, ROLLBACK)

Les moteurs SQL les plus utilisés aujourd'hui : MySQL/MariaDB (très répandus sur le web), PostgreSQL (puissant, open-source), SQLite (léger, embarqué dans les apps mobiles), SQL Server (Microsoft), Oracle (entreprises).

💬
Analogie : Si une base de données est une bibliothèque, SQL est la façon dont vous posez vos questions à la bibliothécaire : "Donne-moi tous les romans publiés après 2010, triés par auteur."
-- Votre première requête SQL
SELECT 'Bonjour SQL' AS message;
Résultat
message
Bonjour SQL
LEÇON 02

Comprendre une Base de Données

Une base de données relationnelle organise les informations en tables liées entre elles par des relations. Ce modèle, inventé par Edgar Codd en 1970, reste le plus utilisé au monde car il garantit cohérence, évitabilité des doublons et facilité d'interrogation.

📚
Analogie : Imaginez une école. Un dossier par élève (table eleves), un dossier par cours (table cours), et un cahier des présences (table inscriptions) qui relie les deux. Chaque dossier est une table, chaque page est une ligne, chaque rubrique est une colonne.
Base de données : ecole
├── eleves (id, nom, prenom, date_naissance, classe_id)
├── cours (id, titre, professeur_id, credits)
├── professeurs (id, nom, specialite)
└── inscriptions (eleve_id, cours_id, note)

Les tables sont reliées via des clés : la table inscriptions contient eleve_id et cours_id qui pointent vers les tables correspondantes. C'est le cœur du modèle relationnel.

💡
Une base de données bien conçue évite la redondance. Le nom du professeur n'est stocké qu'une fois dans la table professeurs — et non répété dans chaque cours qu'il enseigne.
LEÇON 03

Les Tables

Une table est une structure à deux dimensions : des colonnes (les attributs, définis à la création) et des lignes ou enregistrements (les données réelles, ajoutées dynamiquement). Une table bien conçue représente un seul concept ou entité.

CREATE TABLE utilisateurs (
  id    INT,
  nom   VARCHAR(100),
  email VARCHAR(150)
);

-- Pour vérifier qu'une table n'existe pas déjà avant de la créer :
CREATE TABLE IF NOT EXISTS utilisateurs (
  id    INT,
  nom   VARCHAR(100),
  email VARCHAR(150)
);
ℹ️
Bonne pratique : Nommez vos tables au pluriel en minuscules (utilisateurs, non Utilisateur). Les noms doivent être explicites, sans espaces ni accents.

LEÇON 04

Colonnes et Types de Données

Chaque colonne a un type de données qui détermine quelles valeurs elle accepte, combien d'espace elle occupe en mémoire, et quelles opérations peuvent être faites dessus. Choisir le bon type est crucial pour les performances et l'intégrité des données.

INT / BIGINTEntiers. INT va de −2 milliards à +2 milliards. BIGINT pour de très grands nombres (IDs de réseaux sociaux).
VARCHAR(n)Texte de longueur variable jusqu'à n caractères. Idéal pour noms, emails, titres.
TEXTTexte long sans limite fixe. Pour descriptions, articles, contenus.
DATEDate seule : 2025-01-31. Pas d'heure.
DATETIMEDate + heure : 2025-01-31 14:30:00.
FLOAT / DECIMALFLOAT pour données scientifiques approximatives. DECIMAL(10,2) pour les prix (précision exacte).
BOOLEANVrai (1) ou faux (0). Certains moteurs stockent comme TINYINT(1).
ENUMListe de valeurs autorisées : ENUM('actif','inactif','suspendu').
CREATE TABLE produits (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  nom         VARCHAR(200) NOT NULL,
  prix        DECIMAL(10,2) NOT NULL,    -- ex: 12345678.99
  stock       INT DEFAULT 0,
  statut      ENUM('disponible','rupture','archivé'),
  created_at  DATETIME DEFAULT NOW()
);
⚠️
Erreur classique : Utiliser FLOAT pour stocker des prix. Les flottants ont des imprécisions (0.1 + 0.2 = 0.30000000000000004). Utilisez toujours DECIMAL pour les montants monétaires.
LEÇON 05

Créer et Sélectionner une Base de Données

Avant de créer des tables, vous travaillez dans un contexte : une base de données. C'est le conteneur principal qui regroupe toutes vos tables. Un serveur MySQL peut héberger des centaines de bases différentes — chacune isolée des autres.

-- 1. Créer la base
CREATE DATABASE ecole
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 2. La sélectionner comme contexte actif
USE ecole;

-- 3. Lister toutes les bases existantes
SHOW DATABASES;

-- 4. Voir les tables dans la base active
SHOW TABLES;
ℹ️
utf8mb4 est l'encodage recommandé. Il supporte tous les caractères Unicode, y compris les emojis et les alphabets arabes, chinois, etc. N'utilisez jamais simplement utf8 en MySQL — c'est une implémentation incomplète qui ne supporte que 3 octets par caractère.
✦ Exercice pratique

Créez une base boutique en utf8mb4, sélectionnez-la, puis créez dedans une table produits avec les colonnes : id, nom, prix, stock.

Chapitre 2 — Lecture et Filtrage
LEÇON 06

Insérer des Données — INSERT

INSERT INTO ajoute de nouveaux enregistrements dans une table. Vous pouvez insérer une seule ligne ou plusieurs d'un coup — ce qui est bien plus efficace pour les grandes quantités.

-- Insertion simple (spécifier les colonnes = bonne pratique)
INSERT INTO utilisateurs (nom, email)
VALUES ('Aminata Diallo', 'aminata@gmail.com');

-- Insertion multiple en une seule requête (bien plus rapide)
INSERT INTO utilisateurs (nom, email) VALUES
  ('Ibrahima Sow',   'ibrahima@yahoo.fr'),
  ('Fatou Ndiaye',   'fatou@outlook.com'),
  ('Moussa Traoré', 'moussa@gmail.com');

-- INSERT ... SELECT : copier des données d'une table à l'autre
INSERT INTO archive_utilisateurs
SELECT * FROM utilisateurs
WHERE created_at < '2023-01-01';
💡
Toujours spécifier les colonnes dans INSERT. Si vous omettez les noms de colonnes, votre requête échouera dès qu'une colonne est ajoutée ou réordonnée dans la table. INSERT INTO t VALUES (...) est fragile.
LEÇON 07

Afficher les Données — SELECT

SELECT est la commande la plus puissante et la plus utilisée de SQL. Elle interroge une ou plusieurs tables et retourne un jeu de résultats. L'ordre des clauses dans un SELECT est fixe et doit être respecté.

-- Structure complète d'un SELECT (ordre obligatoire)
SELECT   colonnes
FROM     table
WHERE    condition
GROUP BY colonne
HAVING   condition_groupe
ORDER BY colonne
LIMIT    n;

-- Exemples pratiques
SELECT * FROM utilisateurs;                   -- Toutes les colonnes
SELECT nom, email FROM utilisateurs;         -- Colonnes spécifiques
SELECT nom, prix * 1.18 AS prix_TTC FROM produits; -- Calcul à la volée
Résultat — SELECT nom, email FROM utilisateurs
nomemail
Aminata Dialloaminata@gmail.com
Ibrahima Sowibrahima@yahoo.fr
Fatou Ndiayefatou@outlook.com
⚠️
Évitez SELECT * en production : il récupère toutes les colonnes même celles inutiles, surcharge le réseau, et casse votre code si la structure de la table change. Listez explicitement les colonnes dont vous avez besoin.
LEÇON 08

Filtrer avec WHERE

WHERE est le filtre de SQL. Il évalue une condition pour chaque ligne, et ne retourne que les lignes pour lesquelles la condition est vraie. Sans WHERE, la requête traite toutes les lignes de la table — ce qui peut être très lent sur des millions d'enregistrements.

-- Filtrer par valeur exacte
SELECT * FROM utilisateurs WHERE id = 1;

-- Filtrer une chaîne de texte (sensible à la casse selon la configuration)
SELECT * FROM clients WHERE ville = 'Dakar';

-- Filtrer par date
SELECT * FROM commandes
WHERE date_commande >= '2024-01-01'
  AND date_commande < '2025-01-01';

-- Filtrer avec calcul
SELECT * FROM employes WHERE salaire * 12 > 3000000;
🔍
Analogie : WHERE est comme un vigile à l'entrée d'un club. Il examine chaque visiteur (ligne) et ne laisse passer que ceux qui remplissent les critères. La condition est la règle d'entrée.
LEÇON 09

Trier avec ORDER BY

Sans ORDER BY, l'ordre des lignes retournées est indéterminé — le moteur de base de données peut les retourner dans n'importe quel ordre. Si l'ordre compte pour vous, utilisez toujours ORDER BY.

-- Tri alphabétique (ASC par défaut)
SELECT * FROM utilisateurs ORDER BY nom;

-- Du plus cher au moins cher
SELECT * FROM produits ORDER BY prix DESC;

-- Tri multi-colonnes : d'abord par ville, puis par nom dans chaque ville
SELECT nom, ville FROM clients
ORDER BY ville ASC, nom ASC;

-- Trier par un alias ou une expression calculée
SELECT nom, prix * 1.18 AS prix_TTC
FROM produits
ORDER BY prix_TTC DESC;
💡
En SQL, les NULL apparaissent en dernier avec ASC et en premier avec DESC (selon les moteurs). Pour contrôler leur placement : ORDER BY colonne ASC NULLS LAST (PostgreSQL).
LEÇON 10

DISTINCT — Supprimer les Doublons

DISTINCT retourne uniquement les valeurs uniques. Il compare la combinaison complète des colonnes sélectionnées pour déterminer l'unicité.

-- Lister les villes où vous avez des clients (sans doublons)
SELECT DISTINCT ville FROM clients;

-- DISTINCT sur plusieurs colonnes (paires uniques)
SELECT DISTINCT ville, pays FROM clients;

-- Compter les valeurs distinctes
SELECT COUNT(DISTINCT ville) AS nb_villes
FROM clients;

DISTINCT est coûteux sur de grandes tables car le moteur doit comparer toutes les valeurs entre elles. Si vous avez besoin de compter les valeurs uniques fréquemment, envisagez un index ou une table de référence.
LEÇON 11

Les Opérateurs de Comparaison

Ces opérateurs s'utilisent dans les clauses WHERE pour construire des conditions. Ils fonctionnent sur les nombres, les textes, et les dates.

= Égal à. WHERE statut = 'actif'
!= ou <>Différent de. Les deux syntaxes sont équivalentes.
>Supérieur à. Fonctionne aussi sur les dates (date > '2024-01-01').
<Inférieur à.
>=Supérieur ou égal. Inclut la valeur limite.
<=Inférieur ou égal. Inclut la valeur limite.
-- Produits coûtant exactement 5000 FCFA
SELECT * FROM produits WHERE prix = 5000;

-- Commandes passées après le 1er janvier 2024
SELECT * FROM commandes WHERE date_commande > '2024-01-01';

-- Employés dont le salaire n'est pas 200 000
SELECT * FROM employes WHERE salaire != 200000;
ℹ️
Pour comparer à NULL, n'utilisez pas = NULL — cela ne fonctionne jamais. Utilisez obligatoirement IS NULL ou IS NOT NULL (voir leçon 18).
LEÇON 12

AND, OR, NOT — Combiner les Conditions

Ces opérateurs logiques permettent de construire des conditions complexes. L'ordre de priorité est : NOT d'abord, puis AND, puis OR. Utilisez des parenthèses pour clarifier vos intentions.

-- AND : toutes les conditions doivent être vraies
SELECT * FROM employes
WHERE salaire > 300000
  AND ville = 'Dakar'
  AND departement = 'Informatique';

-- OR : au moins une condition vraie suffit
SELECT * FROM clients
WHERE ville = 'Dakar'
   OR ville = 'Thiès'
   OR ville = 'Ziguinchor';

-- Parenthèses ESSENTIELLES pour la priorité
-- ❌ Ambigu — AND s'applique avant OR
WHERE statut = 'vip' OR solde > 1000000 AND anciennete > 2;

-- ✅ Clair et correct
WHERE statut = 'vip'
   OR (solde > 1000000 AND anciennete > 2);
🧮
Table de vérité : AND = les deux doivent être vrais. OR = au moins un doit être vrai. NOT = inverse le résultat. Comme en mathématiques : AND = multiplication, OR = addition de booléens.
LEÇON 13

LIKE — Recherche dans le Texte

LIKE effectue une recherche par motif dans les chaînes de caractères. Deux caractères spéciaux : % remplace zéro ou plusieurs caractères, _ remplace exactement un caractère.

-- Noms commençant par 'A'
SELECT * FROM clients WHERE nom LIKE 'A%';

-- Noms se terminant par 'a'
SELECT * FROM clients WHERE nom LIKE '%a';

-- Emails du domaine gmail.com
SELECT * FROM utilisateurs WHERE email LIKE '%@gmail.com';

-- Codes produit de 6 caractères commençant par 'PRD'
SELECT * FROM produits WHERE code LIKE 'PRD___';  -- 3 tirets bas

-- NOT LIKE : exclure un motif
SELECT * FROM clients WHERE email NOT LIKE '%@gmail.com';
⚠️
LIKE '%texte%' avec un % au début est très lent : le moteur doit scanner toutes les lignes de la table. Pour des recherches full-text performantes, utilisez MATCH ... AGAINST ou un moteur de recherche dédié (Elasticsearch, Meilisearch).
LEÇON 14

BETWEEN et IN — Plages et Listes

BETWEEN teste si une valeur est dans une plage (bornes incluses). IN teste si une valeur appartient à une liste — bien plus lisible que de chaîner des OR.

-- BETWEEN : produits de milieu de gamme (1000 et 5000 inclus)
SELECT * FROM produits
WHERE prix BETWEEN 1000 AND 5000;
-- Équivalent à : WHERE prix >= 1000 AND prix <= 5000

-- BETWEEN sur des dates
SELECT * FROM commandes
WHERE date_commande BETWEEN '2024-01-01' AND '2024-12-31';

-- IN : remplace de multiples OR
SELECT * FROM clients
WHERE ville IN ('Dakar', 'Thiès', 'Saint-Louis', 'Ziguinchor');

-- NOT IN : exclure une liste
SELECT * FROM produits
WHERE categorie NOT IN ('archivé', 'supprimé');
⚠️
NOT IN avec une sous-requête contenant des NULL ne retournera aucun résultat — c'est un piège classique. Si la liste peut contenir des NULL, utilisez NOT EXISTS à la place.
LEÇON 15

LIMIT et OFFSET — Pagination

LIMIT est indispensable pour les performances et la pagination. Sans lui, une requête sur une table de millions de lignes pourrait saturier la mémoire et le réseau.

-- Les 10 premiers résultats
SELECT * FROM articles LIMIT 10;

-- Page 3 avec 10 résultats par page
-- Page 1 : OFFSET 0, Page 2 : OFFSET 10, Page 3 : OFFSET 20
SELECT * FROM articles
ORDER BY created_at DESC
LIMIT 10 OFFSET 20;

-- Formule : OFFSET = (page - 1) × articles_par_page
-- Page 5, 20 par page : LIMIT 20 OFFSET 80
ℹ️
Pagination avec OFFSET et grandes tables : OFFSET 1000000 est lent — MySQL doit quand même lire et ignorer un million de lignes. Pour la pagination haute performance, utilisez la keyset pagination : WHERE id > dernierIdVu LIMIT 20.
✦ Exercice pratique

Écrivez une requête qui retourne les 5 produits les plus chers de la catégorie "Électronique", en affichant uniquement le nom et le prix, triés du plus cher au moins cher.

Chapitre 3 — Modification et Agrégation
LEÇON 16

Mettre à Jour — UPDATE

UPDATE modifie les données existantes. Vous pouvez modifier une ou plusieurs colonnes simultanément. C'est une opération permanente — sans transaction, elle est immédiatement appliquée.

-- Modifier un enregistrement précis
UPDATE utilisateurs
SET email = 'nouveau@gmail.com'
WHERE id = 5;

-- Modifier plusieurs colonnes d'un coup
UPDATE employes
SET salaire    = salaire * 1.10,   -- Augmentation de 10%
    updated_at = NOW()
WHERE departement = 'Informatique'
  AND anciennete >= 3;

-- Mise à jour conditionnelle avec CASE
UPDATE produits
SET statut = CASE
  WHEN stock = 0 THEN 'rupture'
  WHEN stock < 5 THEN 'faible'
  ELSE                'disponible'
END;
⚠️
Règle d'or : Avant tout UPDATE, exécutez le SELECT correspondant pour vérifier les lignes ciblées : SELECT * FROM utilisateurs WHERE id = 5. Confirmez que c'est bien ce que vous voulez. Ensuite seulement, remplacez SELECT * par UPDATE ... SET ....
LEÇON 17

Supprimer — DELETE

DELETE supprime définitivement des enregistrements. Contrairement à TRUNCATE, il déclenche les triggers, respecte les contraintes de clés étrangères, et peut être annulé dans une transaction.

-- Supprimer un enregistrement précis
DELETE FROM utilisateurs WHERE id = 12;

-- Supprimer selon plusieurs critères
DELETE FROM logs
WHERE created_at < DATE_SUB(NOW(), INTERVAL 90 DAY)
  AND niveau = 'debug';

-- Supprimer avec vérification préalable (BONNE PRATIQUE)
-- Étape 1 : Vérifier ce qui sera supprimé
SELECT * FROM commandes WHERE statut = 'annulé' AND YEAR(date) < 2022;
-- Étape 2 : Si OK, procéder à la suppression
DELETE FROM commandes WHERE statut = 'annulé' AND YEAR(date) < 2022;
💡
Soft delete : En production, on préfère souvent ne pas vraiment supprimer. On ajoute une colonne deleted_at DATETIME DEFAULT NULL et on "supprime" en faisant UPDATE ... SET deleted_at = NOW(). Cela permet de récupérer les données supprimées par erreur.
LEÇON 18

Les Valeurs NULL

NULL est une valeur spéciale qui signifie l'absence d'information. Ce n'est pas zéro, ce n'est pas une chaîne vide, ce n'est pas false. C'est l'inconnu. NULL est "contagieux" : toute opération arithmétique ou comparaison avec NULL retourne NULL.

-- Trouver les enregistrements sans valeur
SELECT * FROM utilisateurs WHERE telephone IS NULL;
SELECT * FROM employes WHERE manager_id IS NOT NULL;

-- Piège classique — ne fonctionne JAMAIS
SELECT * FROM utilisateurs WHERE telephone = NULL;     -- Retourne 0 ligne !
SELECT * FROM utilisateurs WHERE telephone != NULL;    -- Pareil : 0 ligne !

-- Calculs avec NULL
SELECT 100 + NULL;   -- Résultat : NULL (pas 100 !)
SELECT SUM(bonus) FROM employes; -- Les NULL sont ignorés dans SUM()

LEÇON 19

Fonctions d'Agrégation

Les fonctions d'agrégation résument un ensemble de lignes en une seule valeur. Elles ignorent les NULL (sauf COUNT(*) qui compte toutes les lignes y compris celles avec NULL).

-- COUNT : compter les lignes
SELECT COUNT(*) AS total_utilisateurs FROM utilisateurs;
SELECT COUNT(telephone) AS avec_tel FROM utilisateurs; -- Ignore les NULL
SELECT COUNT(DISTINCT ville) AS nb_villes FROM clients;

-- SUM, AVG, MIN, MAX
SELECT
  SUM(montant)            AS chiffre_affaires,
  AVG(montant)            AS panier_moyen,
  MIN(montant)            AS plus_petite_commande,
  MAX(montant)            AS plus_grande_commande,
  COUNT(*)                AS nb_commandes
FROM commandes
WHERE statut = 'livré';

LEÇON 20

GROUP BY et HAVING

GROUP BY regroupe les lignes qui partagent la même valeur dans une colonne, puis applique une fonction d'agrégation à chaque groupe. HAVING filtre les groupes après agrégation (comme WHERE filtre les lignes avant).

-- Nombre de commandes par client
SELECT client_id, COUNT(*) AS nb_commandes
FROM commandes
GROUP BY client_id;

-- Chiffre d'affaires par mois, uniquement les mois > 500 000 FCFA
SELECT
  YEAR(date_commande)  AS annee,
  MONTH(date_commande) AS mois,
  SUM(montant)         AS ca_mensuel
FROM commandes
WHERE statut = 'livré'         -- WHERE filtre AVANT GROUP BY
GROUP BY annee, mois
HAVING SUM(montant) > 500000  -- HAVING filtre APRÈS GROUP BY
ORDER BY annee, mois;
📊
Analogie : GROUP BY est comme trier des pièces de monnaie par valeur (1F, 5F, 25F). Chaque pile = un groupe. COUNT(*) = compter les pièces de chaque pile. HAVING = garder seulement les piles de plus de 10 pièces.
ℹ️
Règle : toute colonne dans le SELECT qui n'est pas dans une fonction d'agrégation doit être dans le GROUP BY.
LEÇON 21

Les Alias — AS

Les alias donnent des noms lisibles aux colonnes et aux tables dans les résultats. Ils rendent les requêtes complexes bien plus compréhensibles — pour vous, vos collègues, et les applications qui consomment vos données.

-- Alias de colonnes
SELECT
  nom                        AS "Nom du client",
  email                      AS "Adresse email",
  UPPER(nom)                 AS nom_majuscule,
  DATEDIFF(NOW(), created_at) AS jours_depuis_inscription
FROM utilisateurs;

-- Alias de tables (indispensable pour les jointures)
SELECT c.nom, cmd.montant, cmd.date_commande
FROM  clients   c
JOIN  commandes cmd ON c.id = cmd.client_id;

-- AS est facultatif (mais recommandé pour la lisibilité)
SELECT nom nom_client FROM clients; -- Fonctionne aussi
💡
Les alias de tables courts (une lettre) sont courants pour les jointures complexes (c pour clients, cmd pour commandes), mais sur les requêtes simples, un nom descriptif est préférable pour la lisibilité.
Chapitre 4 — Jointures et Requêtes Avancées
LEÇON 22

Introduction aux Jointures

La normalisation répartit les données dans plusieurs tables pour éviter la redondance. Les jointures (JOIN) permettent de les combiner à nouveau dans une requête, en reliant les tables via des colonnes communes.

Exemple : e-commerce clients (id, nom, email)
commandes (id, client_id, date, montant)
lignes_commande (id, commande_id, produit_id, quantite)
produits (id, nom, prix, categorie_id)
categories (id, nom)

Pour afficher "le nom du client avec ses commandes et les produits commandés", il faut relier 4 tables via leurs colonnes en commun (client_id, commande_id, produit_id).

💡
Les jointures fonctionnent sur le principe des clés étrangères : la valeur d'une colonne dans une table correspond à la clé primaire d'une autre. C'est la "colle" entre les tables.
LEÇON 23

INNER JOIN — L'Intersection

INNER JOIN retourne uniquement les lignes ayant une correspondance dans les deux tables. Si un client n'a pas de commande, ou si une commande n'a pas de client valide, ils n'apparaissent pas dans le résultat.

-- Clients et leurs commandes (uniquement ceux qui ont commandé)
SELECT
  c.nom           AS client,
  cmd.id          AS num_commande,
  cmd.montant,
  cmd.date_commande
FROM        clients   c
INNER JOIN commandes cmd ON c.id = cmd.client_id
ORDER BY   cmd.date_commande DESC;

-- Jointure sur 3 tables
SELECT c.nom, p.nom AS produit, lc.quantite
FROM        clients         c
INNER JOIN commandes       cmd ON c.id = cmd.client_id
INNER JOIN lignes_commande lc  ON cmd.id = lc.commande_id
INNER JOIN produits        p   ON lc.produit_id = p.id;
Résultat — INNER JOIN clients × commandes

LEÇON 24

LEFT JOIN et RIGHT JOIN

LEFT JOIN retourne toutes les lignes de la table gauche, même sans correspondance à droite. Les colonnes de droite affichent NULL quand il n'y a pas de correspondance. C'est le JOIN le plus utilisé après INNER JOIN.

-- Tous les clients, y compris ceux qui n'ont JAMAIS commandé
SELECT
  c.nom,
  COUNT(cmd.id) AS nb_commandes,
  COALESCE(SUM(cmd.montant), 0) AS total_depense
FROM      clients   c
LEFT JOIN commandes cmd ON c.id = cmd.client_id
GROUP BY c.id, c.nom
ORDER BY total_depense DESC;

-- Trouver les clients n'ayant JAMAIS commandé
SELECT c.nom
FROM      clients   c
LEFT JOIN commandes cmd ON c.id = cmd.client_id
WHERE     cmd.id IS NULL;  -- NULL = pas de correspondance trouvée
🤝
Analogie visuelle : Imaginez deux cercles qui se chevauchent (diagramme de Venn). INNER JOIN = l'intersection. LEFT JOIN = tout le cercle gauche + l'intersection. RIGHT JOIN = tout le cercle droit + l'intersection.
LEÇON 25

FULL JOIN et UNION

FULL JOIN retourne toutes les lignes des deux tables, avec NULL là où il n'y a pas de correspondance. UNION combine verticalement les résultats de deux requêtes compatibles.

-- FULL JOIN (MySQL ne le supporte pas nativement — simuler avec UNION)
SELECT c.nom, cmd.montant FROM clients c LEFT JOIN  commandes cmd ON c.id = cmd.client_id
UNION
SELECT c.nom, cmd.montant FROM clients c RIGHT JOIN commandes cmd ON c.id = cmd.client_id;

-- UNION : liste unique de tous les emails (clients + fournisseurs)
SELECT email, 'client'     AS type FROM clients
UNION
SELECT email, 'fournisseur' AS type FROM fournisseurs;

-- UNION ALL : garde les doublons (plus rapide car pas de dédoublonnage)
SELECT * FROM ventes_2023
UNION ALL
SELECT * FROM ventes_2024;
ℹ️
Pour UNION, les deux SELECT doivent avoir le même nombre de colonnes avec des types compatibles. Les noms de colonnes du résultat final sont ceux du premier SELECT.
LEÇON 26

Les Sous-Requêtes

Une sous-requête est une requête SQL imbriquée dans une autre. Elle peut apparaître dans SELECT, FROM, WHERE ou HAVING. Elle s'exécute d'abord, et son résultat est utilisé par la requête externe.

-- Dans WHERE : produits au-dessus du prix moyen
SELECT nom, prix FROM produits
WHERE prix > (SELECT AVG(prix) FROM produits);

-- Dans FROM : transformer en table temporaire
SELECT departement, moy_salaire
FROM (
  SELECT departement, AVG(salaire) AS moy_salaire
  FROM employes
  GROUP BY departement
) AS stats_dept
WHERE moy_salaire > 300000;

-- EXISTS : clients ayant au moins une commande > 50 000 FCFA
SELECT nom FROM clients c
WHERE EXISTS (
  SELECT 1 FROM commandes cmd
  WHERE cmd.client_id = c.id
    AND  cmd.montant > 50000
);
💡
EXISTS est souvent plus performant que IN avec sous-requête sur de grandes tables, car il s'arrête dès qu'il trouve une correspondance. SELECT 1 (au lieu de SELECT *) signifie "peu importe ce qui est sélectionné, je veux juste savoir si au moins une ligne existe".
LEÇON 27

ANY et ALL

ANY vérifie si la condition est vraie pour au moins une valeur de la sous-requête. ALL exige que la condition soit vraie pour toutes les valeurs. Ce sont des opérateurs de comparaison ensemblistes.

-- ANY : produits plus chers qu'au moins UN produit en promo
SELECT nom, prix FROM produits
WHERE prix > ANY (SELECT prix FROM promotions);
-- Équivalent à : WHERE prix > MIN(SELECT prix FROM promotions)

-- ALL : produits plus chers que TOUS les produits en promo
SELECT nom, prix FROM produits
WHERE prix > ALL (SELECT prix FROM promotions);
-- Équivalent à : WHERE prix > MAX(SELECT prix FROM promotions)

-- Cas pratique : employés gagnant plus que tous les stagiaires
SELECT nom, salaire FROM employes
WHERE salaire > ALL (
  SELECT salaire FROM employes WHERE type = 'stagiaire'
);
ℹ️
En pratique, ANY et ALL sont souvent remplacés par EXISTS, IN, ou des sous-requêtes avec MIN/MAX — qui sont généralement plus lisibles et parfois mieux optimisées.

LEÇON 28

Les Index

Un index est une structure de données auxiliaire qui accélère les recherches sur une table. Comme l'index d'un livre, il évite de lire toutes les pages pour trouver un terme. Sans index, MySQL fait un full table scan — il lit chaque ligne une par une.

-- Index simple sur une colonne fréquemment filtrée
CREATE INDEX idx_email ON utilisateurs(email);

-- Index composite (pour les requêtes filtrant sur plusieurs colonnes)
CREATE INDEX idx_ville_statut ON clients(ville, statut);

-- Index UNIQUE (garantit l'unicité ET accélère les recherches)
CREATE UNIQUE INDEX idx_email_unique ON utilisateurs(email);

-- Voir les index d'une table
SHOW INDEX FROM utilisateurs;

-- Supprimer un index inutile
DROP INDEX idx_email ON utilisateurs;
Impact des index sur les performances
SituationSans indexAvec index
Table 100K lignes, WHERE email = ?~80ms~0.5ms
Table 1M lignes, WHERE nom LIKE 'A%'~800ms~5ms
⚠️
Les index ralentissent les écritures (INSERT, UPDATE, DELETE) car ils doivent être mis à jour. N'indexez pas toutes les colonnes : ciblez les colonnes utilisées dans WHERE, JOIN ON, et ORDER BY.
LEÇON 29

Clés Primaires et Étrangères

La clé primaire (PRIMARY KEY) identifie chaque ligne de façon unique et non nulle. La clé étrangère (FOREIGN KEY) établit un lien référentiel entre tables et garantit l'intégrité : vous ne pouvez pas créer une commande pour un client inexistant.

CREATE TABLE clients (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  nom       VARCHAR(100) NOT NULL,
  email     VARCHAR(200) UNIQUE NOT NULL
);

CREATE TABLE commandes (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  client_id  INT NOT NULL,
  montant    DECIMAL(10,2) NOT NULL,
  created_at DATETIME DEFAULT NOW(),

  FOREIGN KEY (client_id) REFERENCES clients(id)
    ON DELETE RESTRICT    -- Interdit de supprimer un client qui a des commandes
    ON UPDATE CASCADE     -- Si l'id client change, mise à jour en cascade
);
ON DELETE RESTRICTInterdit la suppression du parent s'il a des enfants. Comportement par défaut.
ON DELETE CASCADESupprime automatiquement les enfants quand le parent est supprimé.
ON DELETE SET NULLMet la clé étrangère à NULL quand le parent est supprimé.
LEÇON 30

Contraintes NOT NULL et UNIQUE

Les contraintes définissent des règles d'intégrité au niveau de la base de données — la dernière ligne de défense contre des données incohérentes, même si votre application a un bug.

CREATE TABLE utilisateurs (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  nom         VARCHAR(100) NOT NULL,            -- Obligatoire
  email       VARCHAR(200) UNIQUE NOT NULL,     -- Obligatoire + unique
  telephone   VARCHAR(20),                        -- Optionnel (NULL autorisé)
  age         INT CHECK (age >= 0 AND age <= 150) -- Validation de plage
);

-- Ajouter une contrainte sur une table existante
ALTER TABLE produits
  ADD CONSTRAINT chk_prix_positif CHECK (prix > 0);

-- Clé unique composite (la combinaison doit être unique)
ALTER TABLE inscriptions
  ADD UNIQUE (eleve_id, cours_id); -- Un élève ne peut s'inscrire qu'une fois par cours
ℹ️
Une colonne UNIQUE peut contenir des NULL (plusieurs NULL sont autorisés, car NULL ≠ NULL). Si vous voulez une colonne à la fois unique et obligatoire : UNIQUE NOT NULL.
LEÇON 31

Les Transactions — START, COMMIT, ROLLBACK

Une transaction regroupe plusieurs opérations SQL en une unité atomique : soit tout réussit (COMMIT), soit tout est annulé (ROLLBACK). Les transactions respectent les propriétés ACID : Atomicité, Cohérence, Isolation, Durabilité.

-- Transfert bancaire sécurisé
START TRANSACTION;

-- Débiter le compte source
UPDATE comptes SET solde = solde - 50000 WHERE id = 1;

-- Vérifier que le solde n'est pas négatif
SELECT solde FROM comptes WHERE id = 1; -- Si solde < 0 → ROLLBACK

-- Créditer le compte destination
UPDATE comptes SET solde = solde + 50000 WHERE id = 2;

-- Tout s'est bien passé → valider définitivement
COMMIT;

-- En cas d'erreur → annuler tout
ROLLBACK;

-- Point de sauvegarde intermédiaire
SAVEPOINT apres_debit;
-- ... en cas d'erreur partielle :
ROLLBACK TO SAVEPOINT apres_debit;
💡
Par défaut, MySQL est en mode autocommit : chaque requête est automatiquement une transaction. START TRANSACTION désactive ce mode jusqu'au prochain COMMIT ou ROLLBACK.
LEÇON 32

Les Vues — VIEW

Une vue est une requête enregistrée qui se comporte comme une table virtuelle. Elle ne stocke pas de données — à chaque appel, elle exécute la requête sous-jacente. Utile pour simplifier des requêtes complexes, masquer des colonnes sensibles, ou créer des couches d'abstraction.

-- Créer une vue : résumé client avec nombre de commandes
CREATE VIEW vue_clients_resume AS
SELECT
  c.id,
  c.nom,
  c.email,
  COUNT(cmd.id)       AS nb_commandes,
  SUM(cmd.montant)    AS total_depense,
  MAX(cmd.created_at) AS derniere_commande
FROM      clients   c
LEFT JOIN commandes cmd ON c.id = cmd.client_id
GROUP BY c.id, c.nom, c.email;

-- Utiliser la vue comme une table normale
SELECT * FROM vue_clients_resume WHERE nb_commandes > 5;

-- Supprimer une vue
DROP VIEW IF EXISTS vue_clients_resume;
🪟
Analogie : Une vue est comme une fenêtre sur les données. Elle vous montre une perspective particulière sans dupliquer les données. Les changements dans les tables sous-jacentes sont immédiatement visibles à travers la vue.
LEÇON 33

ALTER TABLE — Modifier une Table

ALTER TABLE modifie la structure d'une table existante sans perdre les données. Opération à réaliser avec précaution en production — sur de grandes tables, elle peut prendre plusieurs minutes et verrouiller la table.

-- Ajouter une colonne
ALTER TABLE utilisateurs
  ADD COLUMN telephone VARCHAR(20) DEFAULT NULL;

-- Ajouter une colonne à une position précise
ALTER TABLE utilisateurs
  ADD COLUMN prenom VARCHAR(100) AFTER id;

-- Modifier le type d'une colonne
ALTER TABLE produits
  MODIFY COLUMN description TEXT;

-- Renommer une colonne
ALTER TABLE clients
  RENAME COLUMN tel TO telephone;

-- Supprimer une colonne
ALTER TABLE utilisateurs
  DROP COLUMN colonne_obsolete;

-- Renommer la table
RENAME TABLE anciens_clients TO clients_archive;
⚠️
En production, utilisez des outils comme pt-online-schema-change ou gh-ost pour les ALTER TABLE sur les grandes tables. Ces outils évitent de verrouiller la table pendant l'opération.
LEÇON 34

DROP et TRUNCATE

DROP TABLE supprime la table et toutes ses données. TRUNCATE vide le contenu mais garde la structure. Les deux sont irréversibles sans sauvegarde. Comprendre leurs différences est crucial.

-- TRUNCATE : vide la table (réinitialise AUTO_INCREMENT)
TRUNCATE TABLE logs_temporaires;

-- DROP : supprime table + données + structure
DROP TABLE IF EXISTS table_test;

-- DROP DATABASE : supprime toute la base !
DROP DATABASE IF EXISTS base_dev;
TRUNCATEVide le contenu. Rapide (pas de log ligne par ligne). Réinitialise AUTO_INCREMENT. Ne déclenche pas les triggers. Non annulable.
DELETE sans WHEREMême effet mais lent (logué ligne par ligne). Déclenche les triggers. Annulable avec ROLLBACK.
DROP TABLESupprime tout : données + structure + index + contraintes. Irréversible.
⚠️
Avant tout DROP ou TRUNCATE en production : sauvegardez d'abord (mysqldump), puis vérifiez deux fois le nom de la table. Une faute de frappe peut être catastrophique.
LEÇON 35

AUTO_INCREMENT — Identifiants Automatiques

AUTO_INCREMENT génère automatiquement un entier unique et croissant à chaque insertion. C'est la façon standard de créer des identifiants primaires en MySQL.

CREATE TABLE articles (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  titre     VARCHAR(200) NOT NULL,
  contenu   TEXT,
  created_at DATETIME DEFAULT NOW()
);

-- Insérer sans spécifier l'id
INSERT INTO articles (titre, contenu)
VALUES ('Premier article', 'Contenu ici...');
-- id sera automatiquement 1, puis 2, 3...

-- Récupérer le dernier id inséré (dans la même session)
SELECT LAST_INSERT_ID();

-- Redémarrer le compteur (après TRUNCATE ou pour test)
ALTER TABLE articles AUTO_INCREMENT = 1;

-- Pour de très grandes tables : BIGINT AUTO_INCREMENT
id BIGINT AUTO_INCREMENT PRIMARY KEY
ℹ️
Si un INSERT échoue, le compteur AUTO_INCREMENT est quand même incrémenté. C'est pourquoi vous pouvez avoir des "trous" dans vos IDs (1, 2, 5, 6...). C'est normal et attendu — l'ID ne doit pas représenter une séquence continue.

DEFAULT — Valeur par Défaut

DEFAULT assigne automatiquement une valeur quand la colonne n'est pas spécifiée dans un INSERT. Essentiel pour les colonnes de suivi (dates de création, statuts initiaux, compteurs).

CREATE TABLE commandes (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  client_id  INT NOT NULL,
  montant    DECIMAL(10,2) NOT NULL,
  statut     VARCHAR(50)  DEFAULT 'en_attente',
  priorité   INT          DEFAULT 5,
  created_at DATETIME     DEFAULT NOW(),
  updated_at DATETIME     DEFAULT NOW() ON UPDATE NOW() -- Mis à jour automatiquement
);

-- ON UPDATE NOW() : updated_at se met à jour automatiquement à chaque modification

-- Voir les valeurs par défaut d'une table
DESCRIBE commandes;
💡
La colonne updated_at DATETIME DEFAULT NOW() ON UPDATE NOW() est un pattern très courant. Elle enregistre automatiquement la date de dernière modification sans code applicatif supplémentaire.
LEÇON 37

Fonctions de Chaîne de Caractères

SQL dispose d'un riche ensemble de fonctions pour manipuler le texte directement dans les requêtes. Elles évitent de faire ces transformations dans le code applicatif.

SELECT
  UPPER(nom)                       AS majuscules,     -- 'AMINATA DIALLO'
  LOWER(email)                     AS minuscules,     -- 'aminata@gmail.com'
  LENGTH(nom)                      AS nb_caractères,  -- 14
  TRIM(nom)                        AS sans_espaces,   -- Supprime espaces début/fin
  LTRIM(RTRIM(nom))                AS trim_complet,
  CONCAT(prenom, ' ', nom)         AS nom_complet,    -- 'Aminata Diallo'
  SUBSTRING(email, 1, 10)          AS extrait,        -- 10 premiers chars
  REPLACE(nom, 'Diallo', 'Ba')    AS remplacé,
  LOCATE('@', email)              AS pos_arobase,    -- Position du @
  LEFT(telephone, 2)               AS indicatif       -- '77', '78'...
FROM utilisateurs;
✦ Cas concret

Nettoyer des données importées : UPDATE clients SET nom = TRIM(UPPER(nom)) — supprime les espaces parasites et normalise la casse en une seule requête pour toute la table.

Fonctions de Date et d'Heure

Les fonctions de date permettent d'extraire des composantes temporelles, de calculer des durées, et de formater les dates selon vos besoins — sans passer par le code applicatif.

SELECT
  NOW()                                        AS maintenant,         -- 2025-06-15 14:30:00
  CURDATE()                                    AS aujourd_hui,        -- 2025-06-15
  YEAR(date_naissance)                         AS annee_naissance,
  MONTH(created_at)                            AS mois_inscription,
  DAY(created_at)                              AS jour,
  DAYNAME(NOW())                               AS nom_jour,           -- 'Sunday'
  DATEDIFF(NOW(), created_at)                  AS jours_anciennete,
  TIMESTAMPDIFF(YEAR, date_naissance, NOW())   AS age_en_annees,
  DATE_FORMAT(created_at, '%d/%m/%Y')         AS date_fr,            -- '15/06/2025'
  DATE_ADD(NOW(), INTERVAL 30 DAY)           AS dans_30_jours
FROM utilisateurs;
💡
Cas fréquent : Trouver les utilisateurs inscrits ce mois-ci : WHERE YEAR(created_at) = YEAR(NOW()) AND MONTH(created_at) = MONTH(NOW()). Attention : cette condition empêche l'utilisation des index. Préférez : WHERE created_at >= '2025-06-01' AND created_at < '2025-07-01'.

CASE WHEN — Logique Conditionnelle

CASE WHEN est l'équivalent SQL du if / else if / else. Il peut apparaître dans SELECT, WHERE, ORDER BY, et UPDATE. C'est l'une des fonctionnalités les plus polyvalentes de SQL.

-- Catégoriser les employés par niveau de salaire
SELECT
  nom,
  salaire,
  CASE
    WHEN salaire >= 600000 THEN 'Senior'
    WHEN salaire >= 300000 THEN 'Confirmé'
    WHEN salaire >= 150000 THEN 'Junior'
    ELSE                        'Stagiaire'
  END AS niveau
FROM employes;

-- Pivot : compter par statut dans des colonnes séparées
SELECT
  COUNT(CASE WHEN statut = 'livré'   THEN 1 END) AS livrees,
  COUNT(CASE WHEN statut = 'annulé'  THEN 1 END) AS annulees,
  COUNT(CASE WHEN statut = 'en_cours' THEN 1 END) AS en_cours
FROM commandes;

LEÇON 40

COALESCE et IFNULL — Gérer les NULL

COALESCE retourne la première valeur non-NULL d'une liste d'arguments. IFNULL est sa version simplifiée à deux arguments. Indispensables pour afficher des valeurs lisibles à la place des NULL.

-- COALESCE : premier contact disponible
SELECT
  nom,
  COALESCE(telephone_mobile, telephone_fixe, email, 'Aucun contact') AS contact_principal
FROM clients;

-- IFNULL : version simplifiée (2 arguments)
SELECT
  nom,
  IFNULL(telephone, 'Non renseigné') AS tel,
  IFNULL(bonus, 0) + salaire         AS remuneration_totale -- NULL + salaire = NULL sans IFNULL
FROM employes;

-- NULLIF : retourne NULL si les deux valeurs sont égales (utile pour éviter division par zéro)
SELECT ventes / NULLIF(nb_visites, 0) AS taux_conversion
FROM stats_site; -- Retourne NULL si nb_visites = 0 au lieu d'une erreur
💡
COALESCE est standard SQL et fonctionne sur tous les moteurs. IFNULL est spécifique à MySQL/MariaDB. ISNULL existe dans SQL Server. Pour la portabilité : préférez COALESCE.
LEÇON 41

Les Procédures Stockées

Une procédure stockée est un programme SQL enregistré dans la base, réutilisable à volonté. Elle peut accepter des paramètres, utiliser des variables, des boucles, des conditions. Idéale pour encapsuler une logique métier complexe.

DELIMITER //

CREATE PROCEDURE CreerCommande(
  IN  p_client_id  INT,
  IN  p_montant    DECIMAL(10,2),
  OUT p_commande_id INT
)
BEGIN
  -- Vérifier que le client existe
  IF NOT EXISTS (SELECT 1 FROM clients WHERE id = p_client_id) THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Client introuvable';
  END IF;

  -- Créer la commande
  INSERT INTO commandes (client_id, montant)
  VALUES (p_client_id, p_montant);

  SET p_commande_id = LAST_INSERT_ID();
END //

DELIMITER ;

-- Appeler la procédure
CALL CreerCommande(42, 15000.00, @nouvel_id);
SELECT @nouvel_id AS id_créé;
ℹ️
IN = paramètre d'entrée. OUT = paramètre de sortie. INOUT = les deux. DELIMITER // change le délimiteur pour que MySQL ne confonde pas les ; internes avec la fin de la procédure.
LEÇON 42

Les Déclencheurs — TRIGGER

Un trigger est du code SQL qui s'exécute automatiquement avant ou après une opération (INSERT, UPDATE, DELETE). Il permet d'implémenter des règles métier directement dans la base, indépendamment de l'application.

DELIMITER //

-- Avant suppression : archiver le client
CREATE TRIGGER avant_suppr_client
BEFORE DELETE ON clients
FOR EACH ROW
BEGIN
  INSERT INTO clients_archive (id, nom, email, supprimé_le)
  VALUES (OLD.id, OLD.nom, OLD.email, NOW());
END //

-- Après mise à jour du stock : alerter si stock faible
CREATE TRIGGER apres_maj_stock
AFTER UPDATE ON produits
FOR EACH ROW
BEGIN
  IF NEW.stock < 5 AND OLD.stock >= 5 THEN
    INSERT INTO alertes (produit_id, message, created_at)
    VALUES (NEW.id, CONCAT('Stock faible : ', NEW.stock), NOW());
  END IF;
END //

DELIMITER ;
⚡
OLD contient les valeurs avant la modification. NEW contient les valeurs après. Dans un trigger BEFORE DELETE, seul OLD existe. Dans un AFTER INSERT, seul NEW existe.

Gestion des Utilisateurs et Droits d'Accès

En production, le compte root ne doit jamais être utilisé par les applications. Créez des comptes dédiés avec les droits minimaux nécessaires — principe du moindre privilège.

-- Créer un utilisateur (localhost = connexion locale uniquement)
CREATE USER 'app_user'@'localhost'

-- Révoquer un droit

-- Voir les droits d'un utilisateur
SHOW GRANTS FOR 'app_user'@'localhost';

-- Supprimer un utilisateur
DROP USER 'ancien_employe'@'localhost';

LEÇON 44

Fonctions de Fenêtre — OVER et PARTITION BY

Les fonctions fenêtre (window functions) effectuent des calculs sur un ensemble de lignes lié à la ligne courante, sans agréger les résultats (contrairement à GROUP BY). Disponibles depuis SQL 2003, elles sont parmi les outils les plus puissants de SQL moderne.

SELECT
  nom,
  departement,
  salaire,
  -- Rang global par salaire décroissant
  RANK()         OVER (ORDER BY salaire DESC) AS rang_global,

  -- Rang dans chaque département séparément
  RANK()         OVER (PARTITION BY departement ORDER BY salaire DESC) AS rang_dept,

  -- Salaire moyen de tout le monde (sans grouper)
  AVG(salaire)   OVER ()                          AS moy_globale,

  -- Salaire moyen du département
  AVG(salaire)   OVER (PARTITION BY departement)  AS moy_dept,

  -- Cumul des salaires par ordre d'ancienneté
  SUM(salaire)   OVER (ORDER BY date_embauche)    AS cumul_salaires,

  -- Ligne précédente et suivante
  LAG(salaire)   OVER (ORDER BY salaire)          AS salaire_precedent,
  LEAD(salaire)  OVER (ORDER BY salaire)          AS salaire_suivant
FROM employes;
💡
RANK() laisse des trous (1,1,3). DENSE_RANK() n'en laisse pas (1,1,2). ROW_NUMBER() numérote consécutivement sans ex-aequo.
LEÇON 45

CTE — Common Table Expressions

Les CTE (WITH ... AS) créent des tables temporaires nommées valables le temps de la requête. Elles rendent les requêtes complexes bien plus lisibles et maintenables — et permettent même des requêtes récursives.

-- CTE simple : clients actifs + leurs stats
WITH clients_actifs AS (
  SELECT id, nom, email
  FROM clients
  WHERE statut = 'actif' AND created_at > '2023-01-01'
),
stats_commandes AS (
  SELECT client_id, COUNT(*) AS nb, SUM(montant) AS total
  FROM commandes
  WHERE statut = 'livré'
  GROUP BY client_id
)
SELECT ca.nom, sc.nb, sc.total
FROM      clients_actifs ca
LEFT JOIN stats_commandes sc ON ca.id = sc.client_id
ORDER BY sc.total DESC;

-- CTE récursive : hiérarchie d'employés (manager → sous-ordres)
WITH RECURSIVE hierarchie AS (
  SELECT id, nom, manager_id, 0 AS niveau
  FROM employes WHERE manager_id IS NULL    -- PDG (pas de manager)
  UNION ALL
  SELECT e.id, e.nom, e.manager_id, h.niveau + 1
  FROM      employes  e
  JOIN      hierarchie h ON e.manager_id = h.id   -- Récursion
)
SELECT REPEAT('  ', niveau), nom FROM hierarchie;

La Normalisation des Bases de Données

La normalisation est le processus d'organisation des données pour éliminer la redondance et garantir la cohérence. Elle suit des formes normales progressives. Une base mal normalisée entraîne des anomalies de mise à jour, d'insertion et de suppression.

❌ Table NON normalisée — anomalies garanties commandes(id, client_nom, client_email, client_ville, produit_nom, produit_prix, qte)

Problème : si Aminata change d'email, il faut modifier N lignes.
Si un produit change de prix, toutes ses commandes passées sont affectées. 
-- ✅ 1FN : chaque colonne contient une valeur atomique
-- ✅ 2FN : chaque colonne non-clé dépend de TOUTE la clé primaire
-- ✅ 3FN : chaque colonne dépend directement de la clé, pas d'une autre colonne

-- Solution : 4 tables normalisées
CREATE TABLE clients    (id INT PK, nom, email, ville_id INT FK);
CREATE TABLE villes     (id INT PK, nom, pays);
CREATE TABLE produits   (id INT PK, nom, prix_actuel, categorie_id INT FK);
CREATE TABLE commandes  (id INT PK, client_id FK, created_at);
CREATE TABLE lignes_cmd (id INT PK, commande_id FK, produit_id FK,
                          qte, prix_unitaire); -- Prix au moment de la commande
🏗️
Règle pratique : Si vous mettez à jour une information et devez modifier plusieurs lignes dans plusieurs tables, votre base n'est pas assez normalisée. Chaque fait doit exister en un seul endroit.
LEÇON 48

Sauvegarde et Restauration

Une base de données sans sauvegarde est une bombe à retardement. La règle 3-2-1 : 3 copies, sur 2 supports différents, dont 1 hors site. Voici les outils essentiels.

# ── Dans le terminal (shell), pas dans MySQL ──

# Exporter une base complète
mysqldump -u root -p ecole > sauvegarde_ecole_2025-06-15.sql

# Exporter avec structure + données + procédures stockées
mysqldump -u root -p --routines --triggers ecole > sauvegarde_complete.sql

# Exporter une seule table
mysqldump -u root -p ecole clients > sauvegarde_clients.sql

# Exporter plusieurs bases
mysqldump -u root -p --databases ecole boutique blog > multi_bases.sql

# Compresser pour gagner de l'espace
mysqldump -u root -p ecole | gzip > sauvegarde.sql.gz

# Restaurer depuis un fichier
mysql -u root -p ecole < sauvegarde_ecole_2025-06-15.sql

# Restaurer un fichier compressé
gunzip < sauvegarde.sql.gz | mysql -u root -p ecole
✦ Automatisation — Cron job

Sauvegarde automatique quotidienne à 2h du matin :
0 2 * * * mysqldump -u root -pMOT_DE_PASSE ecole > /backups/ecole_$(date +%Y%m%d).sql

LEÇON 49

Les Injections SQL — Comprendre et Se Protéger

L'injection SQL est l'une des vulnérabilités web les plus dangereuses (classée dans le top 3 OWASP depuis des années). Elle permet à un attaquant de lire, modifier ou détruire votre base de données en insérant du code SQL malveillant dans un champ de formulaire.

-- ❌ DANGEREUX : concaténation directe de l'input utilisateur
input = "' OR '1'='1"   -- Saisie malveillante de l'utilisateur
requête = "SELECT * FROM users WHERE nom = '" + input + "'"
-- Résultat : SELECT * FROM users WHERE nom = '' OR '1'='1'
-- Retourne TOUS les utilisateurs ! Authentification contournée.

-- Attaque encore plus dévastatrice
input = "'; DROP TABLE users; --"
-- Efface toute la table users !
-- ✅ SÉCURISÉ : Requêtes préparées (paramétrisées)

-- PHP avec PDO
$stmt = $pdo->prepare("SELECT * FROM users WHERE nom = ?");
$stmt->execute([$_POST['nom']]);

-- Node.js avec mysql2
const [rows] = await pool.execute(
  "SELECT * FROM users WHERE nom = ?",
  [req.body.nom]
);

-- Python avec mysql-connector
cursor.execute("SELECT * FROM users WHERE nom = %s", (nom_input,))

-- Java avec PreparedStatement
PreparedStatement stmt = conn.prepareStatement(
  "SELECT * FROM users WHERE nom = ?"
);
stmt.setString(1, nomInput);
⚠️
Règle absolue : Ne jamais construire une requête SQL par concaténation de chaînes contenant des données utilisateur. Toujours utiliser des requêtes préparées ou des ORM (Eloquent, SQLAlchemy, Prisma, Sequelize). Même pour une requête "simple".

LEÇON 50

Bonnes Pratiques & Récapitulatif Final

Vous avez parcouru les 50 leçons SQL — des fondements jusqu'aux fonctionnalités avancées. Voici les principes qui distinguent un développeur SQL professionnel d'un débutant.

01
Clés primaires sur chaque tableChaque table doit avoir un INT AUTO_INCREMENT PRIMARY KEY. Jamais de table sans identifiant unique — cela rend les mises à jour et jointures impossibles.
02
Nommer les colonnes explicitementÉcrivez INSERT INTO t (col1, col2) VALUES plutôt que INSERT INTO t VALUES. Votre code survivra aux modifications de structure.
03
Tester le WHERE avant UPDATE/DELETEToujours exécuter SELECT * FROM table WHERE ... et vérifier les lignes retournées avant de lancer un UPDATE ou DELETE. Un WHERE manquant efface tout.
04
Indexer intelligemmentIndexez les colonnes de WHERE, JOIN ON et ORDER BY. Vérifiez avec EXPLAIN. Trop d'index ralentit les écritures ; trop peu ralentit les lectures.
05
Utiliser des transactions pour les opérations critiquesTout transfert d'argent, toute opération multi-tables liée logiquement doit être dans une transaction. Si une étape échoue, tout est annulé.
06
Requêtes préparées sans exceptionJamais de concaténation d'input utilisateur dans une requête SQL. Toujours des requêtes préparées ou un ORM. Zéro exception à cette règle.
07
Normaliser, puis dénormaliser si besoinCommencez toujours par une base normalisée (pas de données dupliquées). Si les performances l'exigent, dénormalisez délibérément et documentez pourquoi.
08
Sauvegarder automatiquementMettez en place un cron job de sauvegarde quotidienne. Testez régulièrement que la restauration fonctionne. Une sauvegarde non testée n'est pas une sauvegarde.

Maîtriser SQL prend des mois de pratique. L'étape suivante : construire de vrais projets — une application web, un tableau de bord analytique, un système de gestion. Chaque requête écrite consolide la compréhension. Bonne continuation. 🚀
