01

Introduction à MySQL

Concept

MySQL est l'un des systèmes de gestion de bases de données relationnelles (SGBDR) les plus populaires au monde. Créé en 1995 et aujourd'hui maintenu par Oracle, il est utilisé par des millions d'applications — des blogs personnels aux grandes plateformes comme Facebook, Twitter ou Airbnb.

💡

Pourquoi une base de données ? Une base de données permet de stocker des informations de manière organisée, persistante et efficace. Contrairement à un simple fichier texte, elle permet de chercher, trier et relier des données en quelques millisecondes.

Exemples de données qu'on y stocke :

  • Utilisateurs et leurs profils
  • Produits d'une boutique en ligne
  • Commandes et factures
  • Messages d'un chat ou d'un forum
  • Articles, images, vidéos d'un blog

MySQL s'intègre avec presque tous les langages de programmation modernes :

LangageFramework populaireConnecteur
PHPLaravel, SymfonyPDO, mysqli
PythonDjango, Flaskmysql-connector, SQLAlchemy
JavaScriptNode.js, Expressmysql2, Sequelize
JavaSpring BootJDBC, Hibernate
✅

Les données stockées dans MySQL sont persistantes : même si le serveur redémarre ou que vous éteignez votre ordinateur, les données sont conservées sur disque.

Concept

Pour démarrer avec MySQL, la méthode la plus simple est d'installer une suite logicielle tout-en-un. Ces packs installent en une seule opération : Apache, PHP, MySQL et phpMyAdmin.

Une fois installée, la suite démarre automatiquement le serveur MySQL. Vous pouvez alors :

  • Accéder à phpMyAdmin via le navigateur

Concept

phpMyAdmin est une interface graphique web qui permet de gérer MySQL sans écrire toutes les commandes à la main. C'est l'outil idéal pour débuter et visualiser facilement vos données.

04

Créer une base de données

DDL

Une base de données est un conteneur logique qui regroupe plusieurs tables. Pensez-y comme un classeur : le classeur = la base de données, les onglets = les tables.

📐 Syntaxe
CREATE DATABASE nom_de_la_base;
SQL
CREATE DATABASE boutique;

-- Avec encodage recommandé (accents, emojis)
CREATE DATABASE boutique
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
✅

Bonne pratique : toujours créer vos bases en utf8mb4 pour supporter tous les caractères (accents, emojis, langues asiatiques).

Pour lister toutes les bases existantes :

SQL
SHOW DATABASES;

Sélectionner une base de données

DDL

Après avoir créé une base, il faut indiquer à MySQL que vous souhaitez travailler dedans. C'est ce que fait la commande USE.

SQL
USE boutique;
⚠️

Si vous oubliez le USE avant vos commandes, MySQL ne saura pas sur quelle base travailler et retournera une erreur : "No database selected".

Pour voir quelle base est actuellement sélectionnée :

SQL
SELECT DATABASE();

Comprendre les Tables

Concept

Une table est la structure fondamentale de stockage en SQL. Elle s'organise comme un tableau avec des colonnes (les attributs) et des lignes (les enregistrements).

IDNomEmailPays
1Aliou Dialloaliou@gmail.comSénégal
2Fatoumata Bahfato@outlook.comGuinée
3Moussa Konémoussa@yahoo.frMali

Chaque ligne représente un utilisateur unique. Chaque colonne représente une propriété partagée par tous les utilisateurs.

💡

Une base de données est constituée de plusieurs tables qui peuvent être reliées entre elles via des clés. C'est le principe fondateur des bases relationnelles (JOIN).

Créer une Table

DDL

La commande CREATE TABLE permet de définir la structure d'une table : ses colonnes et leur type de données.

📐 Syntaxe
CREATE TABLE nom_table (colonne1 TYPE, colonne2 TYPE, ...);
SQL — Exemple complet
CREATE TABLE utilisateurs (
  id    INT,
  nom   VARCHAR(100),
  email VARCHAR(150),
  age   INT
);

Pour voir les tables d'une base :

SQL
SHOW TABLES;

DESCRIBE utilisateurs;

09

Insérer des Données — INSERT INTO

DML

La commande INSERT INTO permet d'ajouter de nouvelles lignes dans une table. C'est l'une des commandes les plus utilisées quotidiennement.

📐 Syntaxe
INSERT INTO table (col1, col2) VALUES (val1, val2);
SQL — Insertion simple
INSERT INTO utilisateurs (nom, email, age)
VALUES ('Aliou Diallo', 'aliou@gmail.com', 25);

Il est aussi possible d'insérer plusieurs lignes en une seule requête :

SQL — Insertion multiple
INSERT INTO utilisateurs (nom, email, age)
VALUES
  ('Fatoumata Bah', 'fato@gmail.com', 30),
  ('Moussa Koné',   'moussa@gmail.com', 28),
  ('Aminata Sow',   'ami@gmail.com', 22);
✅

Insérer plusieurs lignes dans une seule requête est bien plus performant que de faire plusieurs INSERT séparés.

10

Lire les Données — SELECT

Requête

SELECT est la commande la plus utilisée en SQL. Elle permet de récupérer des données stockées dans une ou plusieurs tables.

SQL
-- Toutes les colonnes de tous les utilisateurs
SELECT * FROM utilisateurs;

-- Uniquement le nom et l'email
SELECT nom, email FROM utilisateurs;

-- Renommer les colonnes dans le résultat
SELECT nom AS 'Prénom',
       email AS 'Adresse Email'
FROM utilisateurs;

❌ À éviter

Utiliser SELECT * en production : retourne toutes les colonnes inutilement, surcharge le réseau et ralentit les pages.

✅ Recommandé

Nommer explicitement les colonnes dont vous avez besoin : plus rapide, plus lisible, plus sécurisé.

11

Filtrer avec WHERE

Requête

La clause WHERE est utilisée pour filtrer les données. Sans elle, MySQL retourne toutes les lignes. Avec elle, on cible exactement ce qu'on cherche.

SQL
-- Utilisateur avec l'ID 1
SELECT * FROM utilisateurs WHERE id = 1;

-- Utilisateurs de plus de 18 ans
SELECT * FROM utilisateurs WHERE age > 18;

-- Combinaison de conditions (ET)
SELECT * FROM utilisateurs
WHERE pays = 'Sénégal' AND age > 20;

-- Combinaison de conditions (OU)
SELECT * FROM utilisateurs
WHERE pays = 'Mali' OR pays = 'Guinée';
OpérateurSignification
=Égal à
!= ou <>Différent de
> / <Supérieur / Inférieur à
>= / <=Supérieur ou égal / Inférieur ou égal
IS NULLValeur vide (NULL)
IS NOT NULLValeur non vide
12

Trier les résultats — ORDER BY

Requête

Par défaut, MySQL ne garantit aucun ordre particulier. ORDER BY permet de trier les résultats selon une ou plusieurs colonnes.

SQL
-- Tri alphabétique A→Z
SELECT * FROM utilisateurs ORDER BY nom ASC;

-- Tri du plus récent au plus ancien
SELECT * FROM commandes ORDER BY date_commande DESC;

-- Tri sur plusieurs colonnes
SELECT * FROM produits
ORDER BY categorie ASC, prix DESC;
💡

ASC = Ascendant (croissant, de A à Z, du plus petit au plus grand) — c'est la valeur par défaut.
DESC = Descendant (décroissant, de Z à A, du plus grand au plus petit).

13

Limiter les résultats — LIMIT

RequêtePerformance

LIMIT est essentiel pour la pagination. Il permet de ne récupérer qu'un sous-ensemble des résultats, ce qui améliore considérablement les performances.

SQL
-- 5 premiers utilisateurs
SELECT * FROM utilisateurs LIMIT 5;

-- Page 2 : sauter les 10 premiers, prendre les 10 suivants
SELECT * FROM utilisateurs LIMIT 10, 10;

-- Avec ORDER BY pour la pagination
SELECT * FROM articles
ORDER BY date_publication DESC
LIMIT 0, 10; -- Page 1
✅

Formule de pagination : LIMIT (page-1)*par_page, par_page. Page 3 avec 10 éléments par page → LIMIT 20, 10

14

Modifier des données — UPDATE

DML

UPDATE permet de modifier les valeurs d'une ou plusieurs lignes existantes.

SQL
-- Modifier le nom de l'utilisateur ID 1
UPDATE utilisateurs
SET nom = 'Mamadou Diallo'
WHERE id = 1;

-- Modifier plusieurs colonnes à la fois
UPDATE utilisateurs
SET nom = 'Mamadou', email = 'mamadou@gmail.com'
WHERE id = 1;
🚨

DANGER : Ne jamais oublier WHERE ! Sans WHERE, cette commande modifie toutes les lignes de la table :

UPDATE utilisateurs SET nom = 'Test'; -- ⛔ modifie TOUT le monde
15

Supprimer des données — DELETE

DML

DELETE permet de supprimer des lignes d'une table. Cette action est irréversible (sauf dans une transaction).

SQL
-- Supprimer un utilisateur spécifique
DELETE FROM utilisateurs WHERE id = 5;

-- Supprimer tous les comptes inactifs
DELETE FROM utilisateurs WHERE actif = 0;
🚨

Sans WHERE → vide totalement la table :
DELETE FROM utilisateurs; — supprime tous les utilisateurs définitivement.

💡

Pour vider une table rapidement (sans logs), utilisez plutôt TRUNCATE TABLE nom_table; — c'est beaucoup plus rapide sur les grandes tables.

16

Clés Primaires — PRIMARY KEY

DDLConcept

Une clé primaire est un identifiant unique pour chaque ligne. Elle garantit qu'aucun enregistrement ne sera dupliqué et permet de retrouver exactement un seul enregistrement.

SQL
CREATE TABLE utilisateurs (
  id  INT PRIMARY KEY,
  nom VARCHAR(100)
);

-- Si vous essayez d'insérer deux fois le même ID :
INSERT INTO utilisateurs VALUES (1, 'Ali');
INSERT INTO utilisateurs VALUES (1, 'Moussa'); -- ❌ Erreur : doublon
💡

La clé primaire est obligatoirement unique et ne peut pas être NULL. C'est la colonne de référence utilisée dans les jointures entre tables.

17

AUTO_INCREMENT

DDL

AUTO_INCREMENT génère automatiquement des identifiants uniques qui s'incrémentent à chaque insertion. Vous n'avez plus à gérer manuellement les IDs.

SQL
CREATE TABLE utilisateurs (
  id  INT AUTO_INCREMENT PRIMARY KEY,
  nom VARCHAR(100)
);

INSERT INTO utilisateurs (nom) VALUES ('Ali');    -- id = 1
INSERT INTO utilisateurs (nom) VALUES ('Fato');   -- id = 2
INSERT INTO utilisateurs (nom) VALUES ('Moussa'); -- id = 3
18

NOT NULL, UNIQUE et DEFAULT

DDL

Ces trois contraintes permettent de garantir la qualité et la cohérence des données insérées.

ContrainteRôle
NOT NULLLa colonne est obligatoire (ne peut pas être vide)
UNIQUELa valeur doit être unique dans toute la colonne
DEFAULTValeur utilisée si aucune valeur n'est fournie
SQL — Combinaison des contraintes
CREATE TABLE utilisateurs (
  id    INT AUTO_INCREMENT PRIMARY KEY,
  nom   VARCHAR(100) NOT NULL,
  email VARCHAR(150) NOT NULL UNIQUE,
  pays  VARCHAR(50)  DEFAULT 'Sénégal',
  actif BOOLEAN DEFAULT 1
);

21

Introduction aux Jointures (JOIN)

Concept

Dans une vraie base de données, les informations sont réparties dans plusieurs tables pour éviter la duplication. Les jointures permettent de les combiner dans une seule requête.

❌ Sans jointures

  • Données dupliquées
  • Mises à jour difficiles
  • Incohérences possibles

✅ Avec jointures

  • Données organisées
  • Mises à jour simples
  • Cohérence garantie
💡

Imaginez : la table utilisateurs contient les infos personnelles. La table commandes contient les achats. Le JOIN relie les deux via l'ID utilisateur.

22

INNER JOIN

Requête

INNER JOIN retourne uniquement les lignes ayant une correspondance dans les deux tables. Les utilisateurs sans commande et les commandes sans utilisateur sont exclus.

SQL
SELECT u.nom, c.produit, c.prix
FROM utilisateurs AS u
INNER JOIN commandes AS c
  ON u.id = c.utilisateur_id;
23

LEFT JOIN et RIGHT JOIN

Requête

LEFT JOIN retourne toutes les lignes de la table gauche, même si aucune correspondance n'existe à droite (les colonnes absentes valent NULL).

SQL
-- Tous les utilisateurs, même ceux sans commande
SELECT u.nom, c.produit
FROM utilisateurs u
LEFT JOIN commandes c
  ON u.id = c.utilisateur_id;
TypeLignes retournées
INNER JOINUniquement les lignes communes aux deux tables
LEFT JOINToutes les lignes de la table gauche + correspondances droite
RIGHT JOINToutes les lignes de la table droite + correspondances gauche
25

GROUP BY et HAVING

Requête

GROUP BY regroupe les lignes ayant une même valeur et est souvent utilisé avec des fonctions d'agrégation (COUNT, SUM, AVG…).

SQL
-- Nombre d'utilisateurs par pays
SELECT pays, COUNT(*) AS total
FROM utilisateurs
GROUP BY pays;

-- HAVING : filtrer APRÈS le regroupement
SELECT pays, COUNT(*) AS total
FROM utilisateurs
GROUP BY pays
HAVING total > 10
ORDER BY total DESC;
💡

WHERE filtre avant le regroupement (sur les lignes brutes). HAVING filtre après le regroupement (sur les agrégats).

27

Fonctions d'agrégation : COUNT, SUM, AVG, MIN, MAX

Requête

Ces fonctions calculent des valeurs statistiques sur un ensemble de lignes.

SQL — Les 5 fonctions essentielles
-- Nombre total d'utilisateurs
SELECT COUNT(*) AS total_utilisateurs FROM utilisateurs;

-- Total des ventes
SELECT SUM(prix) AS chiffre_affaires FROM commandes;

-- Prix moyen
SELECT AVG(prix) AS prix_moyen FROM produits;

-- Produit le moins cher et le plus cher
SELECT MIN(prix) AS min_prix,
       MAX(prix) AS max_prix
FROM produits;
⚡ Chapitre 4 — Requêtes Avancées
31

LIKE, IN et BETWEEN

RequêteAvancé

Ces opérateurs permettent d'écrire des conditions de filtrage plus expressives que les simples comparaisons.

SQL — LIKE
-- Noms commençant par "Ali"
SELECT * FROM utilisateurs WHERE nom LIKE 'Ali%';

-- Noms se terminant par "ba"
SELECT * FROM utilisateurs WHERE nom LIKE '%ba';

-- Noms contenant "ou"
SELECT * FROM utilisateurs WHERE nom LIKE '%ou%';
SQL — IN et BETWEEN
-- IN : liste de valeurs
SELECT * FROM utilisateurs
WHERE pays IN ('Sénégal', 'Mali', 'Guinée');

-- BETWEEN : plage de valeurs
SELECT * FROM utilisateurs
WHERE age BETWEEN 18 AND 30;

-- BETWEEN avec des dates
SELECT * FROM commandes
WHERE date_commande BETWEEN '2026-01-01' AND '2026-12-31';
35

Les Vues (VIEW)

AvancéDDL

Une vue est une table virtuelle créée à partir d'une requête SQL. Elle ne stocke pas les données mais les affiche dynamiquement à chaque appel.

SQL
-- Créer une vue
CREATE VIEW vue_clients_actifs AS
SELECT id, nom, email
FROM utilisateurs
WHERE actif = 1;

-- Utiliser la vue comme une table normale
SELECT * FROM vue_clients_actifs;

-- Supprimer une vue
DROP VIEW vue_clients_actifs;
✅

Les vues sont utiles pour simplifier des requêtes complexes, masquer des colonnes sensibles à certains utilisateurs, et réutiliser une logique de filtrage complexe.

36

Les Triggers

Avancé

Un trigger est un bloc de code SQL qui s'exécute automatiquement lorsqu'un événement se produit sur une table (INSERT, UPDATE, DELETE).

SQL — Trigger de journalisation
DELIMITER $$

CREATE TRIGGER log_inscription
AFTER INSERT ON utilisateurs
FOR EACH ROW
BEGIN
  INSERT INTO journal (action, details, date_action)
  VALUES ('Inscription', NEW.email, NOW());
END$$

DELIMITER ;
💡

Dans un trigger, NEW représente la nouvelle ligne insérée/modifiée. OLD représente l'ancienne valeur avant modification ou suppression.

37

Procédures Stockées

Avancé

Une procédure stockée est un programme SQL enregistré dans la base de données, réutilisable à tout moment. Elle peut accepter des paramètres.

SQL
DELIMITER $$

CREATE PROCEDURE rechercherUtilisateur(IN recherche VARCHAR(100))
BEGIN
  SELECT * FROM utilisateurs
  WHERE nom LIKE CONCAT('%', recherche, '%');
END$$

DELIMITER ;

-- Appel
CALL rechercherUtilisateur('Ali');

39

Transactions — START, COMMIT, ROLLBACK

AvancéSécurité

Une transaction est un groupe d'opérations qui doivent toutes réussir ou toutes échouer. Elle garantit l'intégrité des données dans les opérations critiques.

💡

Exemple réel : un virement bancaire = débiter le compte A ET créditer le compte B. Si l'une des deux opérations échoue, tout doit être annulé.

SQL — Exemple de virement
START TRANSACTION;

UPDATE comptes
SET solde = solde - 5000
WHERE id = 1; -- Débit

UPDATE comptes
SET solde = solde + 5000
WHERE id = 2; -- Crédit

-- Si tout s'est bien passé
COMMIT;

-- Sinon, en cas d'erreur
-- ROLLBACK;
CommandeEffet
START TRANSACTIONDémarre une transaction
COMMITValide et rend les changements permanents
ROLLBACKAnnule tous les changements depuis le START
SAVEPOINT nomPoint de sauvegarde intermédiaire
42

Sécurité MySQL

Sécurité

La sécurité d'une base de données est un élément fondamental. Une mauvaise configuration peut exposer des données sensibles ou permettre une destruction totale des données.

SQL — Gestion des utilisateurs
-- Créer un utilisateur dédié (éviter root)
CREATE USER 'app_user'@'localhost'
  IDENTIFIED BY 'MotDePasse$ecur1s!';

-- Accorder uniquement les droits nécessaires
GRANT SELECT, INSERT, UPDATE
  ON boutique.*
  TO 'app_user'@'localhost';

-- Appliquer les changements
FLUSH PRIVILEGES;

-- Voir les droits d'un utilisateur
SHOW GRANTS FOR 'app_user'@'localhost';
🚨

Ne jamais : utiliser le compte root dans une application web, stocker les mots de passe en clair dans la base, exposer MySQL directement sur Internet sans pare-feu.

45

Sauvegardes et Restauration

SécuritéPratique

Une sauvegarde régulière est indispensable. Une panne serveur, une erreur humaine ou une attaque peuvent entraîner une perte totale et irréversible des données.

Terminal (Bash)
# Sauvegarder une base de données
mysqldump -u root -p boutique > sauvegarde_2026-05-31.sql

# Sauvegarder toutes les bases
mysqldump -u root -p --all-databases > toutes_les_bases.sql

# Restaurer une base de données
mysql -u root -p boutique < sauvegarde_2026-05-31.sql
✅

Bonne pratique : automatisez vos sauvegardes avec un cron job (tâche planifiée Linux) et stockez les fichiers dans un endroit séparé du serveur principal (cloud, disque externe).

Optimisation des Performances

Performance

Quand la base grossit (millions de lignes), les performances deviennent critiques. Un index bien placé peut transformer une requête de 10 secondes en 10 millisecondes.

SQL — Indexation
-- Créer un index sur la colonne email
CREATE INDEX idx_email ON utilisateurs (email);

-- Analyser une requête (voir si l'index est utilisé)
EXPLAIN SELECT * FROM utilisateurs
WHERE email = 'aliou@gmail.com';

❌ Lent

  • SELECT * sur grandes tables
  • Pas d'index sur colonnes filtrées
  • Sous-requêtes dans les boucles
  • LIKE '%mot%' (pas d'index)

✅ Rapide

  • Sélectionner uniquement les colonnes utiles
  • INDEX sur les colonnes WHERE et JOIN
  • LIMIT sur toutes les listes
  • LIKE 'mot%' (index possible)

Projet Complet — Base de Données École

Pratique

Appliquons tout ce que nous avons appris en créant une base de données de gestion scolaire complète.

SQL — Projet École
CREATE DATABASE ecole
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE ecole;

CREATE TABLE etudiants (
  id      INT AUTO_INCREMENT PRIMARY KEY,
  nom     VARCHAR(100) NOT NULL,
  prenom  VARCHAR(100) NOT NULL,
  email   VARCHAR(150) UNIQUE NOT NULL,
  date_naissance DATE
);

CREATE TABLE cours (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  titre      VARCHAR(200) NOT NULL,
  credits    INT DEFAULT 3,
  professeur VARCHAR(100)
);

CREATE TABLE inscriptions (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  etudiant_id INT NOT NULL,
  cours_id    INT NOT NULL,
  date_inscription DATETIME DEFAULT CURRENT_TIMESTAMP,
  note        DECIMAL(4,2),
  FOREIGN KEY (etudiant_id) REFERENCES etudiants(id),
  FOREIGN KEY (cours_id)    REFERENCES cours(id)
);

-- Requête utile : étudiants inscrits avec leurs notes
SELECT
  CONCAT(e.prenom, ' ', e.nom) AS etudiant,
  c.titre AS cours,
  i.note
FROM inscriptions i
INNER JOIN etudiants e ON i.etudiant_id = e.id
INNER JOIN cours c     ON i.cours_id    = c.id
ORDER BY etudiant, cours;
